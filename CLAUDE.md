## Repository Overview

This is a NixOS dotfiles repository using flakes, managing two hosts (pc and laptop) with Home Manager integration. The configuration is modular and organized by concern rather than monolithic files.

## Build and Development Commands

### System Management

```bash
# Switch NixOS configuration (recommended - runs Home Manager first)
nh-os-with-home pc
nh-os-with-home laptop

# Alternative: direct NixOS rebuild
nh os switch -H pc
nh os switch -H laptop

# Standalone Home Manager (user environment)
home-manager switch --flake .#ludovic@pc
home-manager switch --flake .#ludovic@laptop
```

### Development Workflow

```bash
nix develop              # Enter dev shell with all tools
nix fmt                  # Format all files (Nix, Markdown, YAML, shell, JSON)
nix flake check          # Run all checks (builds, formatting, linting)
nix flake update         # Update all flake inputs and lock file
```

### Validation and Checks

The `nix flake check` command runs:

- Build verification for both pc and laptop configurations
- nixfmt-rfc-style formatting check
- Nix syntax validation
- deadnix dead code detection
- statix linting (excludes hardware-configuration.nix)
- Pre-commit hooks validation

## Architecture

### Flake Structure

- `flake.nix` - Main entrypoint defining inputs, outputs, and host configurations
- `flake/` - Modular flake components:
  - `checks.nix` - Build validation and linting checks
  - `formatter.nix` - treefmt configuration for multi-language formatting
  - `packages.nix` - Custom package definitions

### Configuration Organization

```
hosts/
├── pc/pc.nix              # PC-specific configuration and hardware
├── laptop/laptop.nix      # Laptop-specific configuration and hardware
modules/
├── nixos/                 # System-level NixOS modules
│   ├── core/              # Base system, boot, networking, users
│   ├── desktop/           # Desktop environments (KDE Plasma, Sway)
│   ├── programs/          # System programs (gaming, virtualization)
│   └── services/          # System services (SSH, keyring, secrets, power)
├── home/                  # Home Manager user environment
│   ├── core.nix           # User account fundamentals
│   ├── desktop/           # Desktop user configs (Plasma, GTK, Sway, XDG)
│   ├── programs/          # User programs (Git, VS Code, Emacs, terminal)
│   ├── packages/          # Organized package lists by category
│   ├── services/          # User services
│   └── hosts/             # Host-specific home configurations
```

### Key Architectural Patterns

**Module Imports**: Both NixOS and Home Manager use hierarchical imports. Top-level modules (`modules/nixos/default.nix`, `modules/home/default.nix`) import category subdirectories, which in turn import specific feature modules.

**Host Specialization**: The `mkHost` function in `flake.nix` creates NixOS configurations with:

- NixOS modules from `modules/nixos/`
- Integrated Home Manager with modules from `modules/home/`
- Host-specific configs from `hosts/<hostname>/`
- Shared overlays for package customization

**Overlays**: Multiple overlays provide:

- `codexFromUnstable` - Latest codex from nixpkgs-unstable
- `qbittorrent510_2505` - qBittorrent 5.1.0 pinned to NixOS 25.05
- `sonarlintHashFix` - Custom SonarLint package with corrected hash
- VSCode extensions and Emacs packages overlays

**Secrets**: Uses agenix for encrypted secrets, with private repository at `git+ssh://git@codeberg.org/lvanasse/secrets.git`

## Coding Conventions

### File Organization

- Use kebab-case for module filenames
- Host configs named `<hostname>.nix`
- Never edit `hardware-configuration.nix` (generated by NixOS)
- Group related functionality in category subdirectories

### Package Management

Packages are organized by purpose in `modules/home/packages/`:

- `development.nix` - Development tools and languages
- `desktop.nix` - Desktop applications and utilities
- `gaming.nix` - Gaming-related packages
- `creative.nix` - Creative and media tools

When adding packages, place them in the appropriate category file.

### Formatting and Style

- Use nixfmt-rfc-style (RFC 166) for Nix code
- 2-space indentation
- camelCase for Nix attributes, kebab-case for package names
- Always run `nix fmt` before committing

### Testing Changes

- For shared module changes, test both pc and laptop builds
- Use `nix flake check` to validate before committing
- Typical workflow: edit → `nix fmt` → `nix flake check` → test on target host

## Commit Guidelines

Format: `scope: brief description`

Common scopes:

- `pc`, `laptop` - Host-specific changes
- `home` - Home Manager user configuration
- `modules` - Shared module changes
- `doc` - Documentation updates
- `fix` - Bug fixes
- `cleanup` - Code cleanup and refactoring

Examples:

- `pc: Enable flathub`
- `home: Add Java support`
- `modules: Update Plasma configuration`
- `fix: resolve ssh-agent conflict`

Commit `flake.lock` after running `nix flake update` to ensure reproducibility.
